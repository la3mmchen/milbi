# 07 – Basic UI

The UI only **reads state files**. It never runs restic or rsync itself. Running a job from the UI spawns `milbi run <job>` as a subprocess.

## `milbi status`

Prints one table row per job: name, kind, destination, last status, last success (e.g. "3h ago"), and duration. `--json` prints the same data as JSON. A `running` status whose job holds no lock is shown as `stale`.

## `milbi tui`

**Job list (start screen)**

- One row per job, with a status color: green for success, yellow for warning, red for failed, grey for never run.
- Shows the last success age.
- Refreshes every 2 seconds.

**Job detail** (`enter`)

- Last run stats, timestamps, the error message if any, and the last 50 lines of the log.

**Keys**

| Key | Action |
|---|---|
| `↑`/`↓` | Move |
| `enter` | Open detail |
| `r` | Run the selected job now, after asking `y/n` |
| `esc` | Back |
| `q` | Quit |
| `?` | Help |

**Display**

- Works in an 80×24 terminal.
- Respects `NO_COLOR`.
- Never shows secrets.

## Acceptance criteria

- [ ] `milbi status` output matches a golden file for a fixture state dir.
- [ ] `milbi status --json` is valid JSON with one entry per configured job.
- [ ] TUI model tests (bubbletea `Update`/`View` with fixture state) cover the list, detail, run confirmation, and quit.
- [ ] Pressing `r` then `y` starts `milbi run <job>`, and the status changes to `running` on the next refresh.
